Section 01

Why Guardrails

A raw LLM call has one hop. Anything that goes wrong has to be caught by prompt wording alone.

Guardrails wraps that hop in a programmable pipeline. Policies live in config; the runtime enforces them deterministically.

Safety
Block jailbreaks inbound. Filter toxic, hallucinated, or PII-leaking output.
Control
Explicit dialog flows keep the assistant on-topic. No system-prompt roulette.
Grounding & Actions
Vet RAG chunks before they reach the prompt. Gate every tool the model can call.
Section 02

Event-Driven Architecture

The runtime doesn't read text. It reasons over a structured event stream.

Events
Things that happen — user messages, bot responses, guardrail triggers.
UtteranceUserActionFinished StartUtteranceBotAction
Actions
Units of work that produce events — LLM calls, Python functions, tool invocations.
execute get_weather(...) generate_bot_reply(...)
Flows
Scripts of expected events and actions — your deterministic behavior rules.
user ask medical advice bot refuse medical advice
Section 02 · Rails

The Pipeline

Every user turn passes through up to five checkpoints. Each rail decides: reject, alter, or allow.

COST · each rail = +1 model call · input + output self-check triples round-trips per turn

Section 03

Install & Project Layout

Install with pip. Configure a folder. Run.

bash — install
$ python3 -m venv venv $ source venv/bin/activate $ pip install nemoguardrails

Python 3.10–3.13 · No GPU needed for the library itself.

python — quickstart
from nemoguardrails import LLMRails, RailsConfig config = RailsConfig.from_path("./config") rails = LLMRails(config) response = rails.generate(messages=[{"role": "user", "content": "Hello!"}])

config/ folder

tree config/
config/ ├── config.yml # models, rails, settings ├── prompts.yml # optional prompt overrides ├── actions.py # custom Python actions ├── config.py # optional init code ├── rails/ │ ├── greeting.co │ ├── topics.co │ └── ... └── kb/ # optional RAG docs
bash — CLI
$ nemoguardrails chat --config ./config --verbose $ nemoguardrails server --config ./config --port 8000

--verbose makes the invisible pipeline visible during demos.

Section 04

config.yml — The Control Panel

One YAML file. Declares models, wires rails, tunes built-ins.

config/config.yml
models: - type: main engine: openai model: gpt-4o-mini - type: self_check_input engine: openai model: gpt-4o-mini rails: input: flows: - self check input - mask sensitive data on input output: flows: - self check output - self check facts dialog: single_call: enabled: true
  • models — fast model for rails, stronger model for conversation.
  • rails.input / output / dialog — wire named flows into each stage.
  • prompts — override built-in templates like self_check_input.
  • rails.config — tune built-in rails: PII types, thresholds, etc.
Section 05

Colang: Two Versions

One language. Two generations. Not interchangeable.

Colang 1.0

Pattern-matched intents map to fixed bot lines. Stable, mature, production default.

rails/topics.co
define user ask about competitors "What do you think of [Competitor]?" define bot refuse to discuss competitors "I'm not able to discuss competitors." define flow user ask about competitors bot refuse to discuss competitors

Colang 2.0

Explicit flows. Async actions. Python-like syntax. Beta — watch for parity gaps.

main.co
import core, llm, guardrails flow main activate llm continuation activate greeting flow greeting user expressed greeting bot express greeting flow bot express greeting bot say "Hello! I'm your assistant."

Label every snippet with its Colang version. The syntaxes diverge.

Section 06

The Five Rail Types

One shape, five stages. Every rail decides: reject, alter, or allow.

Input
When · user message arrives
Reject or alter inbound text — mask PII, rephrase.
Dialog
When · deciding how to respond
Route to action, free LLM generation, or fixed response.
Retrieval
When · RAG chunks fetched
Reject or mask chunks before they reach the prompt.
Execution
When · custom action invoked
Validate and sanitize tool input and output.
Output
When · bot message ready
Reject or alter outbound text — toxicity, hallucination, PII.
Section 07

Custom Actions

Actions are how Colang calls real code — a DB lookup, an API, a LangChain tool.

config/actions.py
from nemoguardrails.actions import action @action(name="validate_user_input") async def check_input(text: str): return len(text) > 0 @action(execute_async=True) async def call_external_api(endpoint: str): response = await http_client.get(endpoint) return response.json()

Call from Colang

rails/weather.co
$is_valid = execute validate_user_input(text=$user_message) $weather = execute get_weather(city=$city_name) bot provide weather info
  • Auto-injected: context, llm, config, events
  • LangChain tools via rails.register_action()
  • Scale out with a separate actions server

Drop actions.py in your config folder. Auto-registered on load.

Section 09

End-to-End Example

A minimal config: redirect a sensitive topic, safety-check every response.

config/rails/topics.co
define user ask medical advice "What should I take for a headache?" define bot refuse medical advice "I'm not able to give medical advice." define flow medical advice user ask medical advice bot refuse medical advice
config/config.yml
models: - type: main engine: openai model: gpt-4o-mini rails: input: flows: [self check input] output: flows: - self check facts - self check output

Medical questions → deterministic redirect. Everything else → grounded and safety-checked before the user sees it.
